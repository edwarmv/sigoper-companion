# Domain Docs

Before exploring the codebase, read:

- `CONTEXT.md` at the repository root;
- relevant records in `docs/adr/`.

Use the terminology defined in `CONTEXT.md` when naming domain concepts in issue titles, proposals, tests, and implementation plans.

If a concept is not yet defined, use `/domain-modeling` to sharpen it and update the glossary when it is resolved.

If an output conflicts with an existing ADR, identify the conflict explicitly instead of silently overriding it.

This repository uses a single-context layout:

```text
/
├── CONTEXT.md
└── docs/
    └── adr/
```
